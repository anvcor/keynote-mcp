# 《星曜35APO》协作经验（2026-11-12 → 11-15：Windows + PowerPoint 草稿、文稿、配音、封面，交 Mac 重做）

这一期是星曜 APO M 35mm F1.7 ASPH.（对照徕卡 APO-Summicron-M 35mm F2 ASPH.），**送测档**（星曜官方送测，有合作 BF）。Windows 上一个主会话从开题做到交 Mac：PPT 草稿 95 页、陪写文稿、TTS 配音、封面、交接包。基础做法照 [35之月.md](35之月.md)，这里只记这期新摸出来的。

## 1. 作者这期的习惯

- **文风**：作者定为「纯学术论文风格」，并要求多一点批判性：区分事实、厂商宣称和推断，交代比较前提和数据局限（`skills/lens-video-script/references/academic-voice.md`）。
- **写作分工**：前两章和第三章大部分是作者自己在飞书写的；Claude 写图31–图35 和总结，再按他的终稿同步。陪写不向他提问，待定项记进课题卡。
- **改 PPT 时作者会自己动手**：删页（图28 全图页、边缘猫眼页、寿司方图页）、调构图（第 79、82–84 页）。所以**每次改之前都重新列一遍现场的页面**，按备注第一行的 `[图N]` 对页，别按记忆里的页号。他删页后会多出一张空白，要顺手删掉。
- **反馈很短**：「再放大一点」「81页再放大」「74不用改」「73做神奇移动」。拿不准是改哪一页时，先做最小的那种改法，在回复里说明另一种理解。
- 回复不带图片，他自己看 PPTX；改完自己用 `view_slide` 渲染检查，再用文字报页号。
- **GitHub**：改 keynote-mcp 后不提交，等他说「推送」。这台 Windows 没配 git 身份，提交时用 `-c user.name=anvcor -c user.email=36370129+anvcor@users.noreply.github.com`（和以前的提交一致），不改全局配置。PowerShell 里提交说明写进文件再 `git commit -F 文件`，`-F -` 配 here-string 会把整段当成路径。

## 2. 页面做法（新增）

- **系列按时间排一列**（第 2 页徕卡 APO-Summicron-M 90 / 75 / 50 / 35）：四张官网透明 PNG 量卡口本体剪影的像素宽，按卡口统一比例（这次官网图本来就同比例，差不到 0.5%）；底边对齐 y=700；白线带箭头（按时间排）。`product_card` 只支持 1–2 款，多款手搭。
- **不同品牌同框比大小**（第 9、87 页）：也按卡口统一（量各自的卡口本体剪影宽，缩到同一个 pt 宽）。俯拍的图看着大，卡口同宽就对。
- **结尾价格页**（第 87 页）：第 9 页复制成四列（列中心 x 300 / 740 / 1180 / 1620，产品图同缩 0.85、底边 y=700，镜头名两行「品牌 / 型号」顶对齐 762，价格标签 150×62.3 居中）。前一页（第 86 页）是星曜单品页，两页的星曜图、名字、标签、白线**改成同名**，切过去是星曜从居中大图缩到第四列、白线伸长。PowerPoint 平滑按对象名配对，名字以 `!!` 开头才一定配得上。
  - 价格口径作者变了三次：首发价（美元）→ 人民币 → 京东价 → **淘宝全新 M 口在售价平均值**，取整到十位，**不带约等号**。查价去掉定金链接、0.01 元占位、二手、其他卡口和离群价，记下几家参与平均，写进备注。改价格文字后圆角标签会自动缩高，要把 AutoSize 关掉、尺寸设回 150×62.3。
- **结构页括线**：括线内侧两端对准镜片下缘边角（相邻两片的右下角 / 左下角），不是光轴上的顶点，不然两群看着挤在一起。cover glass 括进后组。G1/G2 字的上下位置按渲染出来的字形量，不按文本框。
- **两只镜头 Layout 对比**（第 38 页）：同一次 `export_lens_layout` 出（同比例），像面对齐在同一个 x，上下各一只，左侧右对齐两行镜头名。
- **MTF 页型号**：每行一个独立文本框（不在一个框里回车），27 号黑字，行距 40。
- **实拍样张页**（第三章）：
  - 满屏放：宽 1920、3:2 高 1280、y=-100（上下溢出，字幕线警告对满屏照片可以忽略）。5:4 的照片作者会自己重新导出成 3:2。
  - 放大用 `magic_move_step` 只改图片的位置大小。换算：K = 原图像素 ÷ 1920，S = 倍数 ÷ K，宽高 = 原图尺寸 × S，要让 1× 页面上的点 (cx, cy) 落到页面中心，x = 960 − cx·K·S，y = 540 − (cy+100)·K·S。默认 2.5 倍；光斑在原图只有几十像素时用 5 倍（约等于原图 100%），不然看不出色边；作者嫌大就退到 4 倍。
  - 先切原图 100% 局部看清楚再定放大点（合焦处、光斑、色边），讲什么就放大什么：先焦后（带一点合焦）、再焦前、再边缘。
  - 左上角「Shot on <品牌> / <型号>」两行，28 号白字、淡黑阴影（透明 35%、模糊 6、偏移 1.5），软回车换行。压到亮处就挪到右上角（右对齐到 x=1880）或左下角（底边不低于 1000）。同一张照片的几页标注要同名，放大时就原地不动；作者也会故意让它从右上移到左上。
  - 镜头靠 EXIF 的 LensModel 判断；手动镜头的照片没有镜头名，按同一机身、同一天拍的推定，并在交接里写明是推定。
  - 不点名：别人拍的样张，作者要求只留规格（「35mm F2 APO」），连「某国产AA」也不要。
- 作者的成片照片在 `D:\Picture\导出\2026导出`，用 Everything（`es 文件名`）找，秒出；托盘程序没开会报 IPC 错误，先启动它。

## 3. 送测档和合作 BF

- 品牌方给了合作 BF（飞书文档，保密，只看不外传）。BF 里的表达红线要逐条对一遍文稿：不说「便宜版的某品牌」、不陷入谁的 MTF 线更高、不夸大虚化、0.3 m 近摄要说明 M 机黄斑联动只到 0.7 m、竞品对比要报备不拉踩、品牌名写「星曜」不是「星耀」。BF 里标明「不直接对外发布」的厂内数据不用。
- 照红线改总结时，独立判断照样保留（镜身偏短、对焦环起转阻力），厂商说的「量产一致性」写明只测了一支、没法验证。
- 送测档结尾通常要放购买渠道 / 福利，作者没给就不写，记进待确认。

## 4. 文稿、飞书和校对

- 飞书文档正文是懒加载的：在页面里找到最大的滚动容器，一边滚一边按 `data-block-id` / `.ace-line` 收文字，去掉零宽字符再拼。每次 javascript_tool 调用要在 45 秒内返回，长循环放后台跑、分次取结果。
- **在飞书里改字**：Ctrl+F 打开查找，再点「替换」页。**别按 Ctrl+H**，它会把「h」打进正文（这次打进去了，马上删掉了）。每处用够长的原句查找，确认「1/1」再点全部替换；改完滚动全文复查新句都在、旧句全无。
- 校对清单分级给作者：甲方名字（星耀 → 星曜）、意思念反的句子（「不来的」→「不错的」）、去名字后指代变了的句子、错别字、TTS 停顿过长的句号、TTS 读法。他点名的才改。
- **TTS 读法只改本地 docx，飞书保留原样用来发文章**：`64mm → 64毫米`、`61MP → 6100万像素`、型号大小写统一（35APO / 35AA）。
- `get_deck` 返回的备注会截断（结尾带「…」）。要整段读写备注时用 COM 读全文；用截断后的第一行回写会把图注写坏（这次第 87、88 页被写坏过一次，已修）。

## 5. 配音

流程和工具见 [配音.md](../配音.md)（这期重写了）。要点：

- 复刻音色的预付费额度用完后每次合成都弹「后付费」，**先问作者同意按量扣费**。
- 第一次按章整段合成（300–1800 字），作者听出「后半段比前半段快」，Whisper 30 秒窗口证实每个文件都越念越快。改成一段一块（≤160 字）后速度一致，偏快的块调慢语速重做。
- 一块一块点太慢，改成页面里跑脚本（`tools/tts_batch.js`）；Chrome 不允许页面脚本连续下载，音频 POST 回本机 `tools/tts_recv.py`。
- 交付按仓库约定放 `配音/`，带 `段落时间表.csv` 和 `文本/`，剪辑和字幕直接用。

## 6. 价格查询

- 京东、淘宝都在作者自己的 Chrome 里查（他已登录）。搜索页的商品卡片文字用 JS 取出来再过滤，比截图读快。淘宝搜索结果卡片是 `a[href*="item.taobao.com"]` / `detail.tmall.com`。
- 汇率用最近的市场价（这次 1 美元 ≈ 6.67 元、1 日元 ≈ 0.0416 元），来源写进备注。

## 7. 封面

- 作者这期改用 SongRaw 那种：左边一只大镜头（作者实拍、抠图），右边三行英文「品牌 / 焦距 F光圈（光圈数字标红）/ APO ASPH（两个 A 标红）」，底色和标准封面一样 `#2C2C2C`。参考图存在项目 `封面/参考/`，脚本 `封面/make_cover_songraw.py`。文字放在居中 4:3 安全区（x 240–1680）里，镜头可以出画。
- 不要用整张照片渐隐当背景（作者否了），要抠图。
- 抠实拍图（灰色摄影台背景）：先缩到 3000 px，PhotoCraft `layer.removeBackground` 出主体蒙版；它会把镜筒下方的台面和反光一起留下。按原图每行找镜筒真正的边缘（亮度从背景降到很暗的位置），沿这条边切，**镜筒分段变窄的地方不能用一条直线切**（作者一眼看出左下角没扣好）。检查时把抠图贴在深灰底上提亮 2.5 倍看边缘。

## 8. 收尾交 Mac

- 交接说明照 35之月 的格式写在项目里（`交接_Mac_Keynote.md`）：页面清单、SVG 清单、换原图、要看的文字位置、构件动画先问、待作者确认、封面、配音、包里有什么。
- **素材核对**：用 COM 遍历每页的图片，读 `KMCP_FILE` 标签，检查原图在不在项目文件夹里；没标签的（MTF 页、手工插的图）按对象名找到文件写进交接。`tools/extract_svgs.py` 把 SVG 结构图取到 `SVG素材/`。
- **打包**：先用 COM 把打开的 PPT 存盘；跳过 PowerPoint 的锁文件 `~$*.pptx`（读不了，会让打包报错）；照片、mp3、pptx、docx 用不压缩的方式存进 zip，打完 `testzip()` 校验。这期 640 MB。

## 9. 工具的坑

- PowerPoint COM 的 gen_py 缓存坏了时所有调用报「has no attribute 'CLSIDToClassMap'」：删掉 `%TEMP%\gen_py\3.11\91493440-…` 再重开对话；旧对话里可以用 `test/mcp_client.py` 另起一个服务进程。
- 新对话开工先启动 `tools/ppt_clip_cleaner.py`（PPT 复制的内容贴进飞书才是 PNG）。
- `lens_layout.py` 修过一个 bug：像面比所有镜片都高时（M 口小镜头，像高 21.6 mm、镜片最高 12.1 mm），像面竖线被当成比例尺刻度删掉。现在先认像面。
