# 达芬奇：按文稿把幻灯片视频对上配音

典型素材（一期"镜头评测/光学"类视频）：
- `文稿.docx`：正文 + 插图，插图就是幻灯片截图，出现在它要配的那段话前面
- `xxx1-49.mov`：Keynote 导出的整段动画（每页静止约 3 秒，页间有转场；很多页之间夹一张**空白页**做"淡出-淡入"；章节卡页常是"空白→字淡入→停→淡出→空白"）
- `1.mp3`、`2.mp3`…：分段录的配音，按顺序拼起来就是整篇文稿
- Resolve 工程里通常已经有用户手剪好的开头——**那就是风格样板**，先读懂再接着剪

脚本都在 `scripts/`，全部用 `python3 scripts/xxx.py` 调用，工作文件放 scratchpad 的一个工作目录里（下文记作 `$W`）。

## 流程

### 0. 连上 Resolve，看用户已经做了什么
```bash
python3 scripts/inspect_timeline.py            # 当前时间线；也可传时间线名
```
看清：时间线 fps（常见 60，别信 project 级设置）、V1 已有几段、每段源入点、音频放在哪、媒体池有哪些素材还没用（比如 2.mp3 还没导入）。连不上就让用户在 偏好设置 > 系统 > 常规 里把"外部脚本使用"设为"本地"。

把用户已剪部分的**源入点序列**和配音时间对照一遍，归纳他的习惯。本 skill 默认的习惯（来自用户第一次示范）：
- 转场**从那句话开口的时刻开始**，页面约 0.5–1 秒后完整出现
- 一页要停很久时，**重复铺同一段静止帧**（用户手工就是复制粘贴静帧片段），不用变速/定格
- 页间空白页保留一小段（约 16 帧）：淡出→空白→淡入
- 用户剪好的片段一个不动，从它最后一个"未剪的长片段"处接着剪

如果样板显示出不同习惯（比如转场提前半秒、直接硬切），以样板为准，改 plan 参数。

**这期还没有工程**（工程库里找不到这期的名字）：先只读地打开他最近一期同类工程（`lens-bench` 就是本 skill 的样板）看时间线设置，再用 API 新建：`pm.CreateProject(名字)` → **先** `SetSetting('timelineFrameRate','60')`、`timelineResolutionWidth/Height` 设 `3840/2160`（建了时间线后帧率就改不了）→ `ImportMedia` 导入 .mov 和各段 mp3 → `CreateEmptyTimeline('Timeline 1')` → `SaveProject()`。**播放帧率**（`timelinePlaybackFrameRate`）API 设不进去，会留在 24，预览会卡：`videoMonitorFormat` 可以用 API 设成 `HD 1080p 60`，播放帧率要在界面里改（Shift+9 工程设置 > Master Settings > Playback frame rate 填 60 > Save），改完读回确认。这时没有手剪开头，`keep_video_items: 0`，`start` 从第一张空白页末尾开始（`src` = 空白页 end − 8）。背景音乐（A2）等画面和配音定了再加，见第 8 步。

### 1. 读文稿
```bash
python3 scripts/read_docx.py 文稿.docx --out $W
```
打印"段号 文本 [图N]"，并出 `docx_images_sheet.jpg`。**看这张图**，记下每张图配哪一段。标题行（"一 网站内容""结尾"）不念，对应章节卡。

### 2. 切幻灯片视频
```bash
python3 scripts/analyze_slides.py 幻灯片.mov --out $W
```
得到 `holds.json`（每个静止段的源帧区间，`blank` 标出空白页）和 `holds_sheet_*.jpg`。**看缩略图**，把每个 hold 对上文稿插图，列一张表：hold 编号 → 图N / 空白 / 章节卡。

hold 数一般≈幻灯片页数（文件名里的 1-49 就是提示）。如果某页明显缺了（比如章节卡只剩空白、一个 hold 长达 10 秒），说明淡入淡出没被分开——调小 `--pix`（如 0.001）重跑，别硬用。这一步的错误到剪完才会暴露（用户检查时会发现标题"被切了"）。

**用预测的起点核对每一页**（自动播放导出时最可靠）：第 k 页静止段的起点 ≈ Σ(前面每页 3 秒 + 它的转场时长)。转场时长能从 Keynote 读到（`transition properties of slide`）。实测每页起点和预测差在 ±10 帧以内，总帧数差 1 帧。对不上的就是问题页：
- **一个 hold 约 6.5 秒** = 两页没分开。常见于后一页只多了一点东西（对焦箭头、半透明高亮），`--pix 0.001` 能分开大部分；还分不开的，从 `frames_gray.raw` 找出画面开始变化的帧，手工把 hold 切成两段。
- **一页被切成两个短 hold**：黑底页（光斑图）中间有细微闪动。两段合回一段。
- 改完重新编号，让 **hold k = 第 k 页**，后面写 plan 最省事。抽几页最容易错的（被合并过的、章节卡）的中间帧拼图看一眼。

**最后一定要收紧静止段**：
```bash
python3 scripts/refine_holds.py 幻灯片.mov --out $W     # 约 2 分钟
```
`analyze_slides.py` 用小图判断静止，会把下一个神奇移动刚开始的几帧（缓入，字或箭头每帧只动一点）算进静止段。静止画面要重复铺好几遍，每一遍末尾就会"滑一下再跳回去"——作者第一次剪完就指出过：结构页的 G2 在每个小块末尾滑动。这个脚本用 960×540 逐像素比对，把每段收紧到和中间帧完全一样的部分。35之月里结构页→对焦页多出 10–15 帧、章节卡多出 4–6 帧，其余在 ±3 帧以内。铺完可以抽查：重复铺的每一段首帧和末帧逐像素相同。

### 3. 给配音打时间
```bash
python3 scripts/transcribe.py --out $W --clips 1.mp3 2.mp3 --import /路径/2.mp3
python3 scripts/audio_env.py /路径/1.mp3 /路径/2.mp3 --out $W
```
`transcribe.py` 在临时时间线上跑 Resolve 自带语音识别，得到 `asr_*.tsv`（句级起止秒），用完自动删临时时间线。识别文字有繁体/错字无所谓，只拿来对位置。`audio_env.py` 给出静音段，用于找真正开口点（`onset`）和可以切开的停顿（`pause_at`）。

每个 cue 找法：在 asr 里找到该图对应段落的第一句 → 句首时间；如果图对应的是句子中间（逗号后），用静音段在句内定位。

**配音是 TTS 合成的**（项目 `配音/` 文件夹里有 `段落时间表.csv` 和合成时的逐句对齐）：直接用这些时间，不用跑 `transcribe.py`。表里每个段落有所在文件、图号、开口秒，加上该 mp3 在时间线上的偏移就是 cue 时间；段落中间的 cue 用逐句对齐里那个短句的起点（短句内部按音节比例估）。

### 4. 写 plan.json
字段说明见 `scripts/build_edit.py` 顶部注释。要点：
- **时间都是时间线秒**。配音分段后，文件内时间要加上该段在时间线上的偏移
- `keep_video_items` + `start`：保留用户已剪的前 N 段；`start.at_frame` 必须等于第 N 段的结束位置，`start.src` 是被替换的那段原来的源入点
- 每个 cue：`{"t": 开口秒, "slide": 目标 hold, "via": [途经的空白 hold]}`
- **章节卡**（配音里没念）：在上一段话结束后的停顿处把配音切开，后面整体后移约 2.5 秒，章节卡 cue 放在切点，下一页 cue 放在恢复说话的开口点。章节卡若是"空白→字→空白"三段，写成 `{"slide": 字, "via": [前空白]}`，下一页 `via: [后空白]`。章节卡 cue 加 `"label": "章节卡"`，第 11 步生成 B 站章节要用
- 两个 mp3 之间留约 0.6 秒；mp3 的接缝正好是章节卡时留 2.5 秒（章节卡 cue = 上一段最后一句说完 + 0.35 秒）
- `end`：最后一句说完后约 0.5 秒，淡到结尾空白页
- **跳页**：文稿顺序和幻灯片顺序不一致时（作者没改 PPT 的页序），画面跟着配音走：`{"t":…, "slide": B, "via": [A 后面的空白页], "via_in": B 前面的空白页}`。两张空白页画面相同，切口看不出来。要在汇报里说明这是自作主张的编辑决定
- **「续」页**（同一张图的放大、加箭头、加高亮，备注写 `[图N 续]`）：放在段落里讲到那个东西的那句话开口时，不放段首。每页完整显示要 ≥1 秒；一句话塞不下"整页→放大"两步时，整页一淡入完成就接放大（约 cue + 1.3 秒），让放大后的画面多停一会儿

### 5. 预演，自己检查
```bash
python3 scripts/build_edit.py $W/plan.json
```
不改时间线，打印每个 cue 的"该页完整显示时段"，并出 `preview_cues.jpg`（按 cue 顺序，每格 = 转场后 1.6 秒的画面，格数随 cue 数走）。逐格对照文稿检查：画面对不对、章节卡字在不在（暗图也要放大看）、有没有 `!!` 警告（完整显示不足 1 秒、转场被挤掉）。章节卡完整显示约 1.8 秒以上才算看得清。cue 多时再用 `plan_clips.json` 数值核对：每个 cue 后 1.6 秒的源帧是否落在目标页的 hold 里、有没有计划外的页面闪现（跳页写错时会带出中间的页）。

### 6. 执行
```bash
python3 scripts/build_edit.py $W/plan.json --apply
```
自动：复制一份 `<时间线> 备份` → 删掉要重铺的 V1 片段（和音频轨，若 replace）→ 铺入 → 校验无缝隙/与计划一致 → 保存工程。之后只改视频时，把 `audio` 从 plan 里去掉，免得冲掉用户在音频上的设置。

### 7. 音频设置（只能在界面里做）
Resolve 19 的 API 读不到也改不了音频片段的音量和声道映射。用户的标准：**每段音量 -5 dB，Clip Attributes 设为 Stereo，左右两个声道都用 Embedded Channel 1**（单声道 mp3 两边都出声）。用 computer-use 操作，步骤见 `references/resolve-notes.md` 的"音频界面操作"。这一步放在最后——重铺音频会丢这些设置。

### 8. 背景音乐（作者要求时）
作者的习惯：音乐放 A2，每段音量 **-15 dB**；以前用原神原声，曲库在 `~/Documents/项目素材/视频背景音乐/`，古典录音在其中的 `古典（公有领域）/`（附 `来源与授权.md`）。

```bash
python3 scripts/add_bgm.py --measure 曲库文件夹     # 量曲库平均响度，作 target_lufs（他的原神曲库约 -21.7 LUFS）
python3 scripts/add_bgm.py $W/bgm.json             # 每章一首：裁到章节长度、对齐响度、淡入 1.5 s / 淡出 2.5 s，出 48 kHz FLAC
python3 scripts/add_bgm.py $W/bgm.json --apply     # 导入媒体池「背景音乐」、铺到 A2、保存
```
- 每章一首，`at` 取章节卡所在的时间线秒（plan.json 里章节卡 cue 的 t；开场从 0 开始），最后一首到 V1 结尾。淡出正好在下一章开始时结束
- **对齐响度是为了让 -15 dB 保持原来的意思**：新曲子先调到曲库平均响度，再在界面里统一设 -15 dB，听感就和他以前的视频一样
- 曲子比章节短时脚本会提示，换一首或这一章用两首
- 选曲交给作者听：只量过响度的曲子，强弱起伏大的（LRA > 12）安静处可能听不见、响处盖住配音，汇报时点出来；用了 CC BY-SA 的录音要提醒他在简介里署名
- 然后按第 7 步的界面操作，把 A2 这几段音量设为 -15（不用改声道，FLAC 已是立体声）

### 9. 汇报
用中文简短说明：剪到哪、每页怎么对上的、做了哪些**自作主张的编辑决定**（章节停顿、mp3 间隔）并说明怎么撤、需要用户重点看的位置（时间码）、装了什么依赖（没有 ffmpeg 时脚本会 `pip install --user imageio-ffmpeg`）。

## 常见坑（详见 references/resolve-notes.md）
- `AppendToTimeline` 的 `endFrame` 是**闭区间**；视频单位 = 源帧，音频单位 = 按该片段 `FPS` 属性（mp3 常显示 24，在 60fps 的新工程里会显示 60）算的帧——脚本读属性换算，铺完读回音频片段长度核对
- 音频界面操作时，多选状态下单击其中一段不会取消多选；要单独复查一段，先点时间线空白处
- 新建时间线默认用工程帧率（常是 24），和主时间线（60）不同；读帧率一律 `timeline.GetSetting('timelineFrameRate')`
- 静止检测只看相邻帧差会漏掉慢淡入的文字——`analyze_slides.py` 已同时比较"与段首帧的差"和"变化像素占比"
- 用户在 Resolve 里开着模态对话框时别急着点掉，先看清那是不是他在示范要做的设置

### 10. 字幕（作者导出成片后）
作者以前的做法：成片导进剪映识别字幕，导出和成片同名的 SRT（放在 `/Volumes/移动硬盘/达芬奇导出/`，如 `Lensbench导出.mp4` + `Lensbench导出.srt`），再上传或烧进画面。配音是 TTS 时不用识别——文字就是合成用的原文，只要定时间：

```bash
python3 scripts/tts_srt.py 项目/配音 --render /Volumes/移动硬盘/达芬奇导出/<成片>.mp4    # 输出 <成片>.srt
```
- 配音位置从时间线 A1 读，再用波形互相关量出成片里的实际位置（mp3 解码差约 70 ms），各段偏差不一致说明成片不是最新的剪辑，会停下来
- 段落起止来自 `段落时间表.csv`，段内按标点切短句、和语音段对齐。输出末尾列出语速异常的条目（< 3.5 或 > 8 音节/秒），逐条看是对错了位置，还是 TTS 本来就念得快/慢
- 风格照作者以往的 SRT：单行、句末去逗号句号（保留冒号分号）、一般 12–16 字、最宽 24（字母数字按半个字）、提前 0.1 s 出现
- 想要独立核对时，`transcribe.py` 跑 Resolve 语音识别对比句首：文字应一一对上；它的时间常被取整到整秒，不能拿来校准

### 11. 投稿用的章节
```bash
python3 scripts/chapters.py $W/plan.json 文稿.docx       # 输出 "00:00 开场 / 01:17 一 …" 几行
```
时间取章节卡 cue 的 t（向下取整到秒），标题取文稿的「标题 1」段落，按顺序加「一 二 三」。粘进 B 站投稿页 章节管理 > 编辑章节 > 章节文本编辑器。整个投稿流程（封面、标签、字幕上传、Hi-Res、确认后再投）见 keynote-mcp 仓库的 `投稿.md`。
