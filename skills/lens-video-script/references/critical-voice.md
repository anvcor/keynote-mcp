# 批判性评论口吻（默认口吻，2026-09 起）

来源：《网页镜头仿真》一稿。作者逐段改定后，把定稿和 Claude 的几版初稿对照，明确说：
"以后创作应该就是这样的批判性的语言风格了。"下面的规则全部来自这次的取舍——哪些句子他留下了、哪些被删、哪些被当场打回。

## 1. 定位

- 纽约时报 / 华尔街日报式的评论文章：冷静、思辨、敢下判断。**锋利来自准确的事实和清楚的因果，不来自形容词、修辞和梗。**
- 批判的对象是现象和结构：评测行业停留在结果层、仿真数据不公开、"会仿真的 KOL 算、公众接收结论"的分工、流行但没有逻辑的说法。对事不对人。
- **对自己同样批判**，这是可信度的来源：「少数人确实在用光学设计软件评价镜头，本频道也是其中之一。但这类内容有一个共同的缺陷：数据不公开。」「以我们自己为例，过去能做到的，也不过是在视频里放一张Datasheet，请观众暂停抄录。」
- 立场（opinions.md）和数据铁律（SKILL.md）都不变，只是表达方式变了。

## 2. 论证骨架

一节或一篇的推进：**具体现象 → 真正的原因 → 后果（读者因此拿到什么、缺什么）→ 检验或答案。**

- 开场先给一个具体场景，而不是抽象命题：「今天一篇典型的镜头评测，大概是这样的：十几张实拍样张，中心和边缘各放大一次」。
- 下判断前先排除表面原因：「问题不在于媒体不够勤奋。样张和标靶记录的是结果……」
- 技术细节服务于判断。讲 MTF vs Field、离焦光斑、凸轮曲线，是为了说明"截图做不到什么、这里能做到什么"。
- 检验流行说法时：先原样陈述对方的说法 → 说明怎么验证 → 给结果 → 指出这个说法为什么会流行（「它流行的原因只有一个，就是足够简单」）。

技术帧（评测里的 MTF、球差、点列图）仍然是 **画面 → 数据 → 归因**，但结尾不再用俗话或梗收，改成一句后果或判断，或者干脆不收。

## 3. 句子与段落

- **写完整的句子**，用逗号、分号连接；一段 2–6 句。允许逻辑连接词：「更重要的是」「于是」「但」「即便如此」「本质上」。作者在定稿里保留了这些，**不要为了"密度"把文字压成电报体**。
- **信息密度指每一句都推进论证**，不是往句子里塞参数。主波长 546.1 纳米、专利号、图例的冷暖色，这些作者都没有采用；只有当某个数字本身就是论据时才写。
- 段尾可以用一句点出后果：「而这恰恰是理解一支镜头最要紧的部分。」「公众拿到的是结论，而不是可以检验结论的数据。」但不是每段都收，也不拔高。
- 局限要在正文里用一句话说清：「这是几何光斑，不包含衍射。即便如此，焦外的表现已经可以在拍摄之前算出来。」
- 平铺直叙的事实句可以直接写：「该项目网站通过GitHub静态站实现。项目有关代码都可以在GitHub上查阅。」不需要修饰。
- 作者常把一段拆到两张图之间，或者把结尾几帧并成一段。所以**一段只讲一件事**，方便他拆和合。

## 4. 禁止清单（作者当场打回过）

| 写法 | 被打回的原句 | 为什么不行 |
|---|---|---|
| 排比 / 三连 | 「你不能改一片镜片的曲率，不能换一种玻璃，不能挪动对焦组，再看镜头会变成什么样。」 | 作者原话："不要用这种排列。" |
| 口号式对仗收尾 | 「它是一座陈列馆，不是实验室。」「lens-bench要做的是实验室。」 | 这是修辞，不是论证 |
| 比喻 | 同上（陈列馆 / 实验室） | 作者原话："也不要比喻什么。" |
| 预告钩子 | 「至于它算得准不准，这正是本文接下来要回答的问题。」 | 定稿里被删。直接说目的，不吊胃口 |
| 没有证据的指控或断言 | 「比较镜头时最常见的偷换，是拿不同条件下的数字相比，在这里它没有空间。」「第一次……」 | 定稿里被删。"最常见""第一次"都无法证实 |
| 姿态句 | 「不必先相信任何人的截图」 | 定稿里被删。立场由事实体现，不靠表态 |
| 电报体压缩 | 把一节压成 270 字、一帧一句话 | 作者退回到更长、更完整的那一版 |
| 堆参数凑"密度" | 「光谱默认统一为可见光5线、主波长546.1纳米」「专利US 2015/0092100 A1」「冷色是A、暖色是B」 | 没有进入定稿 |
| 网络狠词（在论证句里） | 「露馅」 | 太口语，削弱冷静的语气 |
| 跑题 | 在"网站能做什么"这一节讲 AI 工作流 | 作者原话："不要扯别的。" |

## 5. 初稿 → 定稿对照

**直说目的，删掉钩子和姿态句**
- 初稿：lens-bench想改变的，正是这种分工。它是一个在浏览器里运行的镜头仿真台：读者打开网页，选一支镜头，就能自己算MTF、像差和光路，不必先相信任何人的截图。至于它算得准不准，这正是本文接下来要回答的问题。
- 定稿：lens-bench想改变的，正是看仿真的门槛，以及仿真数据颗粒度。它是一个在浏览器里运行的镜头仿真台：读者打开网页，选一支镜头，就能自己算MTF、像差和光路。

**作者自己补论点：平实、具体**
- 定稿里他加的：并且，对于测量数据的颗粒度体现也不够。没办法详细展示全视场的变化情况。
- 「颗粒度」随后成了全文的一条主线（第二节「一组样张给不出这样的颗粒度」）。作者提出的概念要接住，并在后文呼应。

**锋利 ≠ 修辞**
- 被打回的版本：……但也仅此而已。它几乎不做仿真，LDM也改不了：你不能改一片镜片的曲率，不能换一种玻璃，不能挪动对焦组，再看镜头会变成什么样。它是一座陈列馆，不是实验室。
- 定稿：把镜头的光学设计搬上网页，并不是新鲜事。在PhotonsToPhotos（PTP）上，早就能查到镜头的专利号和光路图。但它的仿真内容很少，LDM也无法修改。／读者看得到一支镜头的结构，却没法动它，也就无从知道改动之后会发生什么，而这恰恰是理解一支镜头最要紧的部分。

**长度：选完整的那一版**
第二节先后有三版：约 520 字的完整论证版、约 270 字的电报体版、塞满参数的"高密度"版。定稿用的是第一版，只做了删改（删掉"偷换"那句、补上"超频到4433"）。

## 6. 词汇

**保留（作者自己的词，放在判断句里分量足）**：虚空贷款、超频（像场）、一塌糊涂、键摄、传声筒、KOL、第一性原理、颗粒度、门槛、分工、封闭。术语照旧：MTF vs Field、LDM、Ray Fan、Cover Glass、Datasheet、FFT MTF。

**默认不再用**：voice.md 里的 UP 主梗和狠词（坠机、肘击、史、依托、原田不语、横批、三连……）、「这，就是……」式的揭晓腔、「当然，」开头的高频口头连接。只有他明确说"用老风格""这期玩梗"时，才回到 voice.md。

## 7. 定稿范例段落（原样，校准语感用，别整句照抄）

> 这种封闭，一部分源于工具本身。Zemax和CODE V是为光学工程师设计的商业软件，对普通读者而言，门槛高得不切实际。于是评价体系形成了一种固定的分工：会仿真的少数KOL负责计算，再把结论分发给公众。公众拿到的是结论，而不是可以检验结论的数据。

> 参数也可以改。收小光圈，或者调整光谱权重，MTF会当场重算。一张截图只能呈现作者选定的那一个条件，而读者真正关心的，往往是条件变了之后会怎样。

> 结果并不需要解读。最大视场的主光线已经无法在镜片的口径之内穿行，边缘的MTF一塌糊涂。一支全画幅镜头，设计像高就是全画幅。多出来的那一圈像场并不存在，更谈不上是厂商额外奉送的余量。把好的边缘表现归功于一个更大的像场，本质上是一笔「虚空贷款」：用一个无法验证的前提，去解释一个没有理解的结果。它流行的原因只有一个，就是足够简单。

> 现在，镜头仿真可以在线完成，观点不必再经由KOL分发，读者也不必做KOL的传声筒。MTF vs Field、球差曲线都是二维函数图，读得懂，就能自己判断曲线为什么这样变化。一条曲线所承载的数学关系，比语言更高效，信息也更致密。但这离真正的去中心化还很远。数据已经公开，读懂一张MTF图，仍然需要读者自己具备基本的光学知识。群众的键摄水平，仍有待提高。
