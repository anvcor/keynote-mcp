# 评论稿骨架（以《网页镜头仿真》为范本）

适用于：工具或项目发布、行业评论、方法论文章（评测行业的问题、仿真数据公开、辟谣流行说法）。
和评测稿的区别：没有"按物距推进"的固定小循环，主线是论证；图主要是界面截图、对比图和示意图。
全文用 critical-voice.md 的口吻。《网页镜头仿真》全文约 20 帧、2500 字左右。

## 骨架

1. **开场（5–7 帧，不设章节标题）**
   - 具体现象：今天的评测长什么样（样张、标靶）。
   - 表面原因之外的真问题：只记录结果，缺第一性原理；数据的颗粒度不够。
   - 同行和自己：用仿真的人不公开数据，本频道也一样。
   - 结构性原因：工具门槛 → KOL 分发结论的分工。
   - 本期要改变什么：直接说目的（门槛、颗粒度、数据公开），不吊胃口。
   - 基本事实：在哪里能用、规模多大（网址、镜头数量）。
2. **一 它能做什么（6–7 帧）**：先承认已有的东西（PTP 能看专利号和光路图），再指出它缺什么（不能改 LDM、仿真少）；然后逐项讲功能，每项都落到"截图做不到、这里能做到"。局限当场说明（几何光斑、不含衍射）。
3. **二 检验流行的说法（5–6 帧）**：同一把尺子的对比（统一哪些变量、哪些按镜头自身规格）→ 原样陈述一个流行说法 → 怎么验证 → 结果 → 为什么这种说法会流行。
4. **结尾（2–4 帧，作者常合并成两三段）**：怎么做出来的（开源、LLM 自动化，给出耗时和成本这类硬数字）→ 做到了什么（不必经由 KOL 分发）→ 还差什么（去中心化还远，读者的读图能力）。不喊口号，不催更。

## 注意

- 一节只讲这一节的事（"不要扯别的"）：功能一节不插开发故事，开发和成本放在结尾。
- 涉及具体镜头的对比要标数据来源（逆向 / 专利）。
- 作者在飞书里会大幅删改，下一节动笔前先把飞书现稿同步回本地（见 SKILL.md「飞书同步」）。
